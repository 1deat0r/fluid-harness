A factory for better agent harnesses.

Fluid-Harness is the lab around an AI agent—not the agent brain itself. It proposes bounded designs, builds fresh candidates, tests them, keeps the evidence, and lets only verified data inform the next round. An archived proposal can be replayed, but only a fresh test can earn adoption.

Step 01 · propose
Suggest a finite architecture configuration

A process-isolated proposer can suggest finite planner-plus-policy configurations from registered building blocks. The factory can optionally query selected verified archive evidence, compute the evaluation fingerprint, label each suggestion NOVEL or REPEATED, explicitly archive the untested batch, and later send that exact batch through fresh evaluation and replay.

Boundary It cannot invent arbitrary code or grant its own proposal authority.

Explicit boundary

What it cannot do yet

These limits are deliberate safety and scope boundaries, not hidden promises.

?Not present

Invent arbitrary new architectures

It searches combinations of registered components. It does not dream up unrestricted representations or novel source code.

⌘Not present

Rewrite or train itself

The improvement surface is narrow and permit-based. The runner, planner, tools, core, and module code stay outside it.

↥Not present

Deploy or run forever

There is no automatic production deployment, open-ended autonomy, or claim that a candidate should keep operating unsupervised.

◌Not present

Use broad real-world access

Live credentials, broad external tools, durable semantic memory, and unrestricted sandboxing remain future scope.

≠Not proven

Guarantee better intelligence

A passing benchmark or a retained receipt is evidence about that test. It is not proof of general intelligence, AGI, or ASI.

⚠Operator needed

Make high-stakes decisions alone

Research handoffs and sensitive actions remain bounded and operator-facing. The factory is a lab instrument, not a replacement for judgment.
