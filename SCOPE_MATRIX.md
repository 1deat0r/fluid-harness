# Fluid-Harness scope matrix

Fluid-Harness is currently the first runnable control-and-evidence slice of the cognitive-architecture plan. This matrix separates behavior that exists in the kernel from capabilities that are only represented as policy, metadata, or future direction.

The Harness Factory now exposes a verified, capped Pareto-style frontier over same-benchmark generation summaries, plus a bounded portfolio of those frontiers across distinct archived benchmark contracts. Each frontier report counts comparable adopted/rejected generations, holdout dispositions (`FAILED`, `NOT_RUN`, `PASSED`), and failed-to-passed recovery transitions; `factory.history()` also returns a capped summary-only timeline so pruned failures and recoveries remain inspectable. Each entry and lifecycle report carries its derived holdout status from the verified archive/evaluation path. An improvement can default to the newest generation or explicitly target an older verified `baselineGeneration` after another benchmark partition has been archived; that target must be present, earlier, and contract-compatible while the global predecessor chain remains linear. This makes unseen validation, recovery history, and branch-specific iteration visible without turning them into selection authority. It is historical comparison evidence only: it does not select a winner, restore runtime authority, or deploy an architecture.

The factory can also receive a small disjoint `holdoutCases` suite. An adopted bundle must pass a fresh, independently replayed holdout with complete production coverage and proof obligations before its generation is archived as successful; a failed holdout is retained only as a rejected, data-only disposition after candidate retirement, and both outcomes can be summarized to later archive-informed proposers as `holdout-passed` or `holdout-failed` keywords.

`factory.recommend()` adds a read-only next-step hint over verified history: it prioritizes recovery of an unresolved failed holdout, then validation of an unvalidated latest generation, then strict improvement, with `NO_HISTORY` for an empty factory. Archived explicit validation records now count as verified holdout dispositions for that advisory without becoming new generations. The result is a bounded frozen summary only; it never runs work, mutates the ledger, or grants deployment authority.

`factory.researchAgenda()` derives a broader capped, ranked experiment backlog from the same verified history: unresolved holdout recovery, unseen validation, skeptic weaknesses, transfer gaps, and strict improvement. Agenda items retain only measured fitness, holdout status, benchmark identity, and read-only archive locators; they are advisory and do not execute, mutate, invent executable code, or transfer authority.

`factory.researchPlan()` projects that agenda into frozen, data-only experiment plans. Each plan identifies the applicable bounded bridge, operator-facing method, required fresh inputs, and expected evidence for the target; it remains a planning handoff and never executes, restores runtime artifacts, mutates history, or transfers authority. `factory.executeResearchPlan(planItem, options)` can dispatch an exact current plan item through an existing bounded recommendation, holdout, benchmark-validation, frontier-completion, or frontier-stability bridge, while operator-only experiments remain explicit handoffs and stale or forged plans fail closed.

`factory.benchmark()` evaluates a fresh trusted architecture at finite caller-supplied budget levels, independently replays each level, rejects architecture-definition drift, and returns bounded summary points plus a compute/fitness Pareto frontier. It is evaluation evidence only: it does not adopt, deploy, archive, or restore the candidate.

`factory.benchmarkCampaign()` extends that bounded measurement to multiple fresh trusted architectures on one shared finite budget ladder. It uses fresh multi-candidate search/reproduction runners per level, rejects shared planner/policy definitions and cross-level architecture drift, and returns only candidate/level summaries plus a cross-candidate Pareto frontier; it does not adopt or deploy any candidate. `factory.archiveBenchmarkCampaign()` can persist that result as a separate hash-chained data-only record, and restore returns plain summaries without candidates, runners, reports, or authority.

`factory.benchmarkCampaigns()` exposes a capped, read-only history of archived campaign summaries for the exact factory. It verifies the current chain, filters foreign-factory records, and returns no live candidates, runners, reports, or authority. Archived campaigns can also become an observed-only structured-memory source; `factory.improve()` can explicitly query that source so a fresh process-isolated proposer receives campaign evidence before the normal strict-improvement and proof gates, without restoring a candidate or granting authority.

`factory.executeRecommendation()` provides a bounded operator-controlled bridge only for recovery and strict-improvement recommendations. It requires fresh caller-supplied candidates, cases, budgets, and durable archival, binds the request to the exact current recommendation, and routes through the existing improvement/holdout gates. `factory.validateRecommendation()` now lets the caller supply an explicitly reconstructed fresh candidate for an unseen holdout; the factory checks its configuration fingerprint and returns pass/fail data without adoption or archival mutation. `factory.archiveValidation()` persists that result as a separate hash-chained, data-only validation record; restore returns the record as evidence only, and a verified pass/fail result informs the next advisory without creating a generation or transferring authority. History still never restores a live candidate automatically.

`factory.improve()` defaults to the newest archived generation, but a caller can now name an older verified `baselineGeneration` to continue improving that benchmark branch after another partition has been recorded. The selected baseline is checked against verified history and the same benchmark contract; the new generation still links to the latest archive as its global predecessor, so branch-specific comparison does not create an alternate or unverified ledger.

## End-state in plain language

The intended destination is a reusable harness architect and research control tower in which increasingly capable agents can propose ways to think, build new bounded harness configurations, test those configurations against independent evidence, learn from surprises, archive the results, retire failed configurations, and adopt only reproducible improvements under operator-controlled limits.

That makes Fluid-Harness enabling infrastructure for more capable agents. It is not itself a trained general intelligence, an ASI system, or a guarantee that ASI will emerge. Reaching that territory would require future model capability, richer environments, durable memory, broader tools, independent evaluation, and a real process/OS security boundary.
